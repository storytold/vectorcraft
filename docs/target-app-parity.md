## How this was measured (2026-10-10)

- **Target version.** Illustrator 2026, the 30.x line. Feature set from Adobe's public documentation and release
  announcements: 30.0 (October 2025: font browser, gradient dither and perceptual blending, tangent and
  perpendicular snapping, artboard locking and colours, Turntable beta, Firefly integration), 30.2 (TIFF in
  Export for Screens), 30.3, 30.5 (Concept to Vector, Prompt to Edit, Rewrite Text) and 30.7 (Blend panel with
  ease in/out). Sources: the [30.0 announcement](https://community.adobe.com/questions-652/illustrator-2026-v30-0-font-browser-color-snapping-artboards-enhancements-turntable-and-more-1546612),
  the [30.7 announcement](https://community.adobe.com/announcements-651/illustrator-30-7-new-blend-panel-ease-in-out-blends-generate-artwork-with-firefly-bug-fixes-and-more-1635245)
  and helpx feature pages.
- **The installed Illustrator was not inspected.** Illustrator 2026 is installed on the owner's Mac, but this
  repo's clean-room rule ([`AGENTS.md`](../AGENTS.md), from the project owner) forbids reading anything inside an
  Adobe install, its `Info.plist` and `.lproj` folders included, and forbids launching or measuring it. So
  nothing here is a menu dump or a side-by-side measurement: the numbers come from our own code against
  Illustrator's public documentation.
- **From the code (measured, origin/main `01e165af`):**
  - Menu tree (`crates/ui-egui/src/menus.rs`, laid out in Illustrator's menu order): 347 items bound to
    commands, 28 stubs (`todo(…)`/`todos(…)`), so 92.5% of menu items do something. The stubs: Effect ›
    3D and Materials (5), Effect › SVG Filters, Edit › Spelling (3), Graph › Design/Column/Marker (3), Live Paint
    Gap Options, Optical Margin Alignment, Start Global Edit, global and video rulers (2), Snap to Glyph,
    Window › Arrange (4), SVG Interactivity, the library placeholders (3), Other Script…, Help.
  - Engine commands: ~710 ids registered with `cmd!` across `crates/engine/src/cmd` (plus macro-generated
    families), and 85 UI-only commands (`UI_COMMANDS`).
  - Tools: 91 in `crates/tools/src/catalog.rs`; Touch Type is listed but not implemented, and the Dimension
    tool (added in Illustrator 28.x) is absent.
  - Effects catalogue (`crates/effects/src/lib.rs`): see [effects-parity.md](effects-parity.md).
  - Tests: 4,924 `#[test]` functions plus 40 property-test blocks (was "~2,840" in the last estimate).
    ~354k lines of Rust (was ~221k on 2026-10-07).
  - Formats: the `FORMATS` table in `crates/engine/src/cmd/fileio/mod.rs`, see
    [file-format-parity.md](file-format-parity.md).
  - Languages: row counts of `crates/ui-egui/src/i18n/*.tsv`, see [localization-parity.md](localization-parity.md).
- **From users:** the 71 open GitHub issues on 2026-10-10, which show what real users hit first (Illustrator
  `.ai` files opening with the wrong layer structure #951/#868, guides lost from `.ai` #779, Shape Builder
  region detection #937/#893, launch failures on some Windows and Linux machines #858/#964/#620, pen pressure on
  macOS #852, Preferences options that do nothing #394).
- **Presence is not parity.** Each area is scored by behaviour against the public documentation, and an area is
  100% only when every feature in it behaves like Illustrator. Scores were set by the agents that built the
  features, so they are upper bounds; this pass lowered the ones contradicted by open issues.

## Ready for real work

Two numbers, because the professionals who use VectorCraft mostly live in a subset of Illustrator:

| | Value | Kind |
|---|---|---|
| **Mainstream illustrator** (pen, shape and path editing, type, colour, gradients and swatches, artboards and layers, live effects and appearance, SVG/PDF/PNG export, opening their own `.ai` files) | **~65%** (60–70%) | estimated |
| **Full Illustrator** (every area, including 3D, the Effect Gallery, CJK composition, scripting, generative AI) | **~55%** (50–60%) | estimated; decides the stage |

Both start from feature depth over the areas concerned: **~83%** over the 16 mainstream areas (weight 83 of
105: selection, drawing, path operations, colour, strokes, appearance, live effects, type core, symbols and
blends, layers and artboards, view, guides, file formats, Export for Screens, UI chrome, print), **~75%** over
all of them. Each is then discounted by about ×0.9 for interaction fidelity, ×0.92 for stability on real
machines and ×0.92 for Illustrator-file exchange (83 × 0.9 × 0.92 × 0.92 ≈ 63; 75 × the same ≈ 57). The
dimensions a typical illustrator rarely hits (plug-in ecosystem, generative AI, pen tilt, languages beyond
their own) are **not** in either number; they cost the full-parity hours, not readiness.

The discounts, with the evidence:

- **Illustrator's own files (×0.92).** `.ai` and EPS open as editable art by reading their PDF/PostScript and the
  structure of the editing data. Users do open legacy files a lot: 28 of the 350 issues (8%, ~22 people) are
  about `.ai`/EPS, the most common single format theme. 20 of the 28 are fixed (often the same day). The 8 open
  ones are about structure, not missing art: layers flattened or multiplied (#951: 109 layers instead of 14;
  #868), guides lost (#779), slower opening (#758), live effects, brushes and symbols as their drawn look
  (#637). VectorCraft can't write Illustrator's editing data (undocumented), so its `.ai` opens in Illustrator
  as plain art. That blocks beta (the main-format rule) for people who hand files back to Illustrator users,
  but it doesn't stop someone opening and reworking their own archive.
- **Interaction fidelity (×0.9).** Pen, Direct Selection, smart guides and snapping are deep
  ([ui-parity.md](ui-parity.md)), and there has never been a side-by-side session. The issue tracker says the
  details mostly hold: 79 issues are about core drawing (pen, paths, selection, snapping, transform), 68 of them
  (86%) closed, 11 open (#991, #975, #955, #973 among them). One practitioner wrote "0 learning curve from
  pretty heavy AI use over last 20+ years" (#541).
- **Stability on real machines (×0.92).** The code never panics by design, and the main platform (macOS) starts
  reliably, but 26 issues mention a crash, freeze or failed launch (8 open: #858, #964 fixed the day of this
  review, #620, #818, #905 on Windows 7, #834). There is no field record and no real-world file corpus yet.
- **Performance unverified.** Budgets (`vectorcraft-cli perf`) haven't been run on an idle machine since
  2026-10-01; the last loaded run missed the 16 ms frame budget at 50k paths. Not discounted separately: no
  user has reported slowness in mainstream work beyond #575 (Linux AppImage) and #758 (`.ai` open time).
- **Missing subsystems** a minority need daily (3D, the Effect Gallery, CJK vertical composition, scripting)
  pull the full number below the mainstream one.

The discounts a beginner actually hits:

- **Launch and stability, ×0.93:** fine on macOS, but some Windows machines fail to start (#858, #620, #818).
- **Discoverability and UI clarity, ×0.92:** the layout follows Illustrator's and comes in 11 languages, but
  there is no in-app help (Help › VectorCraft Help… is a stub), no Learn panel or tutorials, and a newcomer
  meets Illustrator's density without Illustrator's learning material.
- **Opening files people send them, ×0.96:** PDF, SVG, images and most `.ai` files open as editable art.
  Layer-structure problems (#951) matter less to a beginner.

91 × 0.93 × 0.92 × 0.96 ≈ 75: **~75% (70–80%), estimated.**

## Calibration

Hours come from this repo's own history (git log and merged-PR timestamps, `gh pr list`):

- **Raster filters**, one agent working serially on [gap 2](gaps.md): Pixelate (4 filters, merged 2026-10-10
  08:47), Texture (6, 12:44), Distort (3, 16:24). About 4 h per batch, **0.7–1.2 h per Photoshop-style
  filter** including dialog, catalogue row, menus and translations into 11 languages.
- **M3 (paint and appearance):** a 92-task plan whose packages were planned at 5–11 h each took about
  1–1.5 agent hours each, on 2026-10-04/05 with 6–8 agents.
- **Medium features:** about 0.8 h each (Text Wrap, Graphs, Effect › Pathfinder…: ~20 in ~16 h on 2026-10-02).
- **Whole repo:** 1,671 commits and 592 merged PRs from 2026-09-30 to 2026-10-10, with several agents in
  parallel and a dozen community contributors.

Large subsystems (3D, CJK composition, generative AI) have no comparable history and are counted bottom-up,
with a wider range. What needs a human: native-speaker review of the translations, an owner decision on
generative models, real Illustrator files that users own (used locally, never committed), and Wacom/pen
hardware for tilt and rotation.

## Where we already beat Illustrator

Exact curve booleans, off-thread multithreaded rendering, unlimited undo, lossless SVG/PDF export of live effects,
a documented JSON format, Affinity 1–3 import, the same app on the web and on Linux/FreeBSD, scrubby numeric fields,
sandboxed WebAssembly plug-ins, and every command, gesture and dialog drivable by agents (MCP, CLI, control channel).

## Out of scope (by design or by law)

- **Adobe cloud services** (Libraries sync, Adobe Fonts, Projects, Express templates, Firefly): pluggable
  provider APIs at most, never built in.
- **Adobe's bundled assets** (swatch, brush, symbol libraries, presets, icons): ours are original.
- **Illustrator's private editing data, beyond its structure:** see
  [file-format-parity.md](file-format-parity.md#illustrators-private-editing-data).

## Honest assessment by dimension (2026-10-05)

The previous assessment's evidence per dimension, kept as it was; the [By dimension](#by-dimension) table above supersedes its numbers.

**In one line:** about two-thirds to three-quarters of Illustrator's features exist and work, and for everyday
vector illustration (drawing, paths, paint and appearance, SVG/PDF/print) VectorCraft is close to usable. Measured
against "a power user can't tell the difference", it is closer to 40–55%. What stands between here and "anyone can
switch" is a handful of large subsystems plus a fidelity pass, not a long tail of small fixes.

**How much to trust the numbers:** area scores are graded by the agents that built the features, from behaviour docs
(`plan/illustrator/`) and tests, not by side-by-side use of Illustrator. Treat them as upper bounds. Look & feel is
the only dimension measured against the reference app. Performance budgets haven't been re-run on an idle machine
since 2026-10-01.

## Evidence: what ships today, by area

- **Architecture:** 19+ crates with enforced layering (`cargo xtask layers`). Every action is a command (~400 engine + ~50 UI). Undo is unlimited via structural sharing. `command.batch` runs several commands as one transaction.
- **Automation:**
  - Actions panel (record/playback, persisted), generic parameter dialogs for every "…" command.
  - Variables (data merge): text and visibility variables bound to objects (an object may carry several), dataset rows applied in one undo step (`variable.*`, `dataset.*`) from a Variables panel and Window › Variables, with dialogs to define, bind and edit, Make Text/Visibility Dynamic, Capture/Update Data Set, and a row in italics when an edit leaves the art not matching it; bindings let go of deleted art and locked art is left alone; every command, like the rest, is drivable over MCP and the CLI.
  - JSON-lines control channel with real egui pointer and keyboard injection.
  - MCP server with 25 tools (drawing, text, effects, Pathfinder, transforms, graphs, text wrap, export, screenshots, any command), attached to the running app or headless. Tool descriptions and replies agree with the engine: format lists come from its format table, `save_file` says it keeps the document's own format, `inspect_document` reports the paint type's characters show, and selection exports report the encoder's warnings. `--automation-read-root` / `--automation-write-root` (on `vectorcraft-cli mcp` and on `vectorcraft --control`) confine the files commands read and write to chosen folders, links followed, with the flags PhotoCraft takes (#832).

- **Performance:** 20k shapes + 1k texts render in 27 ms per full-retina frame (7.8 ms zoomed), 7× faster than the first version. The UI thread never blocks. The web build is 7.1 MB gzipped.
- **Graphics processor:** the canvas is rasterized on the CPU and the GPU only composites it, so any GPU that can show the window will do. Preferences › Performance › Graphics Processor (`gpuPreference`) is Automatic by default: the power-saving GPU on Windows and macOS (the integrated one on hybrid-graphics laptops, where presenting from the discrete GPU made the window flicker, #306), and the GPU the desktop runs on under Linux, where KWin on an NVIDIA GPU refused frames from a Ryzen's integrated GPU and 0.5.0 crashed at startup (#502). The app picks among the adapters that can present to the window (native backends before OpenGL, hardware before software, and on Windows a GPU's DX12 adapter before its Vulkan one: Intel's Vulkan driver made the whole window flicker black, #545), and if the window fails on one while starting up it starts again without it instead of crashing; Help › About, `ui.inspect` and the log name the adapter in use. The desktop app writes the copies and says to restart (#369).
